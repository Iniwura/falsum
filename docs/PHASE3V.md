# Phase 3V — show the real recorded model failure, not a scripted quiz

**Preview only.** This is a separate, public-safe judge exhibit. It **does not replace** the current Vercel website, register an evaluator, run new inference, publish confidential Anjoman questions, or claim a win.

## The product question

**Can the model's ranking change when the actual installed software version changes?**

FALSUM originally built hand-authored security-review comparisons. Those were understandable but not evidence that an actual model evaluates correctly. For judges, we now present the **real scored research records** of an actual ModelBERT/ModernBERT LoRA checkpoint loaded through Telegraph's pinned official Foundation/ONNX/WASI runtime.

**Measured result on two known historical families:** 8 unique actual scored inputs, each scored twice; **16 real prior inferences**. The model selected the same one of two researcher-authored candidate responses in both affected and fixed contexts for both libraries. Its preferred response agreed with the previously observed runtime-dependent provisional expectation in **2 of 4 contexts** and it completed **0 of 2** correct context-reversal families. **The model failed this diagnostic.**

These are not newly generated answers; they are the exact previously recorded model scores. The two possible security-review response strings are **researcher-authored**, not generated by the model. The runtime-based better-response expectation is a **provisional research rule**, not independently certified AppSec ground truth. The families were previously inspected and **not** a blind holdout, so 2/4 must not be called the model's overall security accuracy.

## Actual historical runtime evidence

- **Starlette, affected 0.26.1 vs patched 0.27.0.** A safe same-prefix outside-root sibling was returned 200 in a controlled, real installed-library 0.26.1 test and 404 in the patched 0.27.0 test. The recorded model still chose the "exposed" explanation in both contexts. [Actual independent library CI](https://github.com/Iniwura/falsum/actions/runs/41409503521) · [Original model inference](https://github.com/Iniwura/falsum/actions/runs/41411984601).
- **Requests, affected 2.30.0 vs patched 2.31.0.** In-memory reconstruction of a credentialed HTTPS proxy request added `Proxy-Authorization` before the fix and not after. No network request, real credential or actual proxy exfiltration was involved. The recorded model still chose the "absent" explanation in both contexts. [Actual independent library CI](https://github.com/Iniwura/falsum/actions/runs/41410209502) · [Original model inference](https://github.com/Iniwura/falsum/actions/runs/41411984601).

```bash

cd falsum
PYTHONPATH=src python3 -m falsum.phase3v_recorded_model_demo --out-dir real-model-preview
python3 -m http.server --directory real-model-preview 8765
```

Open `http://localhost:8765`. Switch **Starlette / Requests** and **Affected / Fixed**. The candidate texts and actual recorded scores stay source-bound. The UI displays the model's winner next to what the previously executed runtime evidence supports. The actual score record is exported to `real-model-preview/recorded-model-evidence.json`.

The generator validates original per-input **float32 bit patterns**, exact model SHA256, model preference, historical source/runtime evidence, known family identities, 0/2 reversal failures and all no-release conditions. It refuses overwrite and unsafe JSON HTML injection. No model or API account is required, and it makes no new external calls.

## Limits and next honest decision

The failure is evidence against this *particular* model in these research contexts, not evidence that a different model or a new FALSUM model now fixes the ranking. The original and subsequently retrained LoRA checkpoints remain quarantined. No expert-labelled independent holdout, registered evaluator adapter or third-party security-review integration is demonstrated.

The distinct **20 Anjoman-eligible `SECURITY_REVIEW_GENERAL` evaluation preference pairs** are real network contribution evidence under the account, with a public [bounty `/submit` comment](https://github.com/telegraphprotocol/bounties/issues/96#issuecomment-6588168396) pending maintainer approval. **They are not the published historical Starlette/Requests test inputs**, and their confidential texts must not be revealed.

**Next practical research gate:** obtain at least one genuine independent security reviewer to adjudicate new, source-backed cases, then run a truly fresh model comparison on them. Keep the production site unchanged until the preview demonstrates an obvious, independently verifiable contribution and the user approves the product direction. The hackathon final entry, real 2–5 minute walkthrough and independent developer reproduction are separate tasks; the official December 1 submission must still be completed.
