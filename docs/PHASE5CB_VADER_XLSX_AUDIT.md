# Phase 5CB — VADER graded workbook cross-format audit

## Why this phase exists

Phase 5CA authenticated the pinned VADER CSV files but found 60 malformed physical records in graded.csv, 12 source-identity mismatches, two invalid source-metadata records, and four unmatched source IDs. It correctly stopped before any candidate scoring.

The same immutable Hugging Face revision also publishes a separate 918 kB graded.xlsx workbook. Its file page exposes SHA-256 `9da644c6e9012fe124b95bd4460853ba045cafe78d26110e5cedde34dc20f158` and Xet hash `0326e16365c63e3e7ad11c0a89cf4ca88ab8d2f4f44da3682512ff36544ad5fe`. Phase 5CB freezes those exact identifiers and checks whether the workbook provides a structurally sound serialization of the same scored records.

This is a second file in the same dataset revision. It is **not** an independent dataset, a corrected revision, or evidence of candidate improvement.

## Frozen inputs

- Dataset: [AfterQuery/VADER](https://huggingface.co/datasets/AfterQuery/vader), CC-BY-4.0.
- Revision: `9bef4b3b1994ce138d8a043b68ab0d8a81d8472d`.
- Workbook: `graded.xlsx`, SHA-256 and Xet identity pinned in [the Phase 5CB protocol](../data/phase5cb-vader-xlsx-protocol.json).
- Source metadata: the already authenticated `vader.csv`, with its Git blob SHA-1 inherited from the frozen Phase 5CA protocol.
- CSV comparison: `graded.csv`, also authenticated against its original Git blob SHA-1.
- Join key: stable `ID` only. Displayed Case numbers are never join keys.
- Holdout: the Phase 5CA score-blind, repository-grouped SHA-256 rule. Known public FALSUM repositories are excluded. The source inventory is partial.
- Candidate scoring, training, inference, and network upload are out of scope.

## Audit behavior

The script:

1. Downloads the workbook only from the pinned Hugging Face revision and checks the exact SHA-256 before parsing.
2. Opens the workbook read-only with a pinned openpyxl version and requires exactly one worksheet with the frozen Phase 5CA graded schema.
3. Validates stable IDs, source metadata, all six model responses, component-score ranges, and component-to-total sums.
4. Joins the workbook to authenticated source metadata by stable ID and reports unmatched IDs and metadata mismatches.
5. Compares workbook rows with the valid rows from the original CSV. It reports content differences and unmatched IDs without repairing or selecting records.
6. Writes only aggregate counts, hashes, and a score-blind holdout roster. Raw model answers and human scores are not uploaded as artifacts.

Any workbook/CSV difference is a blocker requiring source-owner resolution before candidate scoring. The audit does not decide which representation is correct.

## Reproduction

Python 3.11:

    python -m pip install --no-deps openpyxl==3.1.5
    PYTHONPATH=src python -m unittest discover -s tests -p 'test_phase5cb_vader_xlsx_audit.py' -v
    PYTHONPATH=src python -m falsum.phase5cb_vader_xlsx_audit --out /tmp/PHASE5CB-VADER-XLSX-MANIFEST.json --roster /tmp/PHASE5CB-VADER-HOLDOUT-ROSTER.json

The [Phase 5CB GitHub Actions workflow](../.github/workflows/phase5cb-vader-xlsx-audit.yml) repeats the authenticated download and publishes only the aggregate manifest and score-blind roster. That workflow is author-operated CI, not independent reproduction.

## Decision gate

Candidate scoring may proceed only if the workbook has exactly 174 data rows, no parse or duplicate-ID errors, valid complete six-model responses, no source metadata mismatch, at least 100 matched cases, and at least 20 reserved holdout cases across 20 repositories. Any CSV/XLSX content difference or unmatched ID between the two answer representations must first be resolved by the source owner; no post-hoc repair is permitted.

Even if the gate passes:

- The public holdout is only disjoint from the listed public FALSUM source inventory.
- Overlap with the 20 private Anjoman rows is **UNKNOWN**.
- Model-pretraining overlap is **UNKNOWN**.
- VADER model answers are generated by six external LLMs, not human-authored answers.
- Pairwise preferences derived from aggregate human scores are not original pairwise labels.
- No Telegraph network improvement, active pool usage, accepted material, or official score is implied.
